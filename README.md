## 学习原则

1. **以官方文档为唯一主线**，每读一节立刻敲一遍，不复制粘贴。
2. **每阶段必须有可运行的产出**，没有产出的阶段不算完成。
3. **先跑通再优化**，不要一开始就上微服务、DDD、消息队列。
4. **代码进 Git**，每个阶段结束打一个 tag，方便回看成长轨迹。

## 阶段 0：前置知识（约 1 周）

### 知识点

- [ ] Python 类型注解：`Optional`、`list[dict]`、`TypedDict`、`Literal`
- [ ] 装饰器与闭包（`Depends` 的底层就是它）
- [ ] `async/await` 基本概念：协程、事件循环、什么时候会阻塞
- [ ] HTTP 基础：方法、状态码、Header、JSON、REST 风格
- [ ] SQL 基础：`SELECT` / `INSERT` / `JOIN`、主键外键、索引

### 验收标准

能口头讲清「浏览器输入 URL 到后端返回 JSON」中间发生了什么，并说出 200/201/400/401/403/404/422/500 各自的含义。

## 阶段 1：入门（3–5 天）

### 知识点

- [ ] 安装 `fastapi` + `uvicorn`，跑起第一个 `app`
- [ ] 路由 `@app.get` / `@app.post`，路径参数、查询参数
- [ ] 请求体：`pydantic.BaseModel` 与字段校验（`Field`、`min_length` 等）
- [ ] 响应：`response_model`、`status_code`、`HTTPException`
- [ ] 自动文档：`/docs`、`/redoc`、`openapi.json`
- [ ] `uvicorn main:app --reload` 的热重载

### 验收标准

写一个 5 个接口的「待办事项」API（列表、详情、新建、修改、删除），全部能在 `/docs` 里点通，参数非法时返回 422。

---

## 阶段 2：核心机制（约 1 周）

### 知识点

- [ ] `APIRouter` 拆分路由，`prefix` + `tags`
- [ ] **依赖注入 `Depends`**（本阶段重点）
  - [ ] 普通依赖、类依赖
  - [ ] `yield` 依赖（用于数据库会话、资源释放）
  - [ ] 依赖嵌套与复用（如「当前登录用户」）
- [ ] 中间件（请求耗时、请求 ID）
- [ ] `lifespan` 生命周期管理
- [ ] CORS 配置（前后端分离必备）
- [ ] 全局异常处理器 `exception_handler`
- [ ] `pydantic-settings` 读取 `.env` 配置

### 验收标准

把阶段 1 的项目拆成多文件结构，端口、数据库地址、密钥全部走环境变量，不硬编码。

```
app/
├── main.py
├── core/        # 配置、安全
├── api/         # 路由
├── schemas/     # Pydantic 模型
└── ...
```

## 阶段 3：数据库（1–2 周，最花时间）

### 技术选型（二选一）

| 方案 | 优点 | 适合 |
|---|---|---|
| **SQLModel** | 上手快，FastAPI 作者出品，模型与 Schema 合一 | 快速出原型 |
| **SQLAlchemy 2.0** | 生态最全，企业通用，异步支持成熟 | 长期项目（推荐） |

### 知识点

- [ ] 建表、会话管理（`Session` / `AsyncSession`）
- [ ] 增删改查、条件查询、排序
- [ ] 关系：一对多、多对多（如 用户–流水–分类）
- [ ] **Alembic 数据库迁移**（必须会，否则改表只能删库）
- [ ] 分页（`limit` / `offset`）、过滤、模糊搜索
- [ ] 事务与回滚
- [ ] N+1 查询问题与 `selectinload` / `joinedload`

### 验收标准

待办事项数据落库；用 Alembic 完成至少一次字段变更（新增字段并升级成功）；列表接口支持分页与过滤。

## 阶段 4：认证与权限（约 1 周）

### 知识点

- [ ] 密码哈希：`argon2` 或 `passlib[bcrypt]`（不要自己写加密）
- [ ] `OAuth2PasswordBearer` + JWT 登录流程
- [ ] Token 签发、校验、过期处理
- [ ] 用 `Depends` 实现「获取当前用户」
- [ ] 基于角色的权限控制（普通用户 / 管理员）
- [ ] 越权访问的资源归属校验

### 验收标准

完成注册、登录、拿 token 访问受保护接口；不带 token 返回 401，带别人的 token 访问他人资源返回 403。

## 阶段 5：工程化（1–2 周）

### 知识点

- [ ] 分层结构：`api/` `models/` `schemas/` `services/` `core/` `db/`
- [ ] 统一响应格式与统一错误码
- [ ] 日志配置（结构化日志、请求日志）
- [ ] 测试：`pytest` + `httpx.AsyncClient` + 独立测试数据库
- [ ] 代码质量：`ruff`、`mypy`、`pre-commit`
- [ ] `.env.example`、README、依赖锁定

### 验收标准

`pytest` 一键跑通，至少覆盖登录与 CRUD 主流程；`ruff check` 与 `mypy` 无报错。

## 阶段 6：进阶选学（1–2 周，按需）

- [ ] 异步数据库（`asyncpg` / `aiosqlite`）与连接池调优
- [ ] Redis 缓存（热点统计接口）
- [ ] 限流（`slowapi`）
- [ ] 后台任务：`BackgroundTasks`、Celery / ARQ

## 实战：贴合本项目的落地安排

把阶段 3 之后的内容直接做成「大学生个人消费记账与管控系统」的后端，避免学完没处用。

### 模块与接口设计

| 模块 | 接口设计 |
|---|---|
| 用户 | 注册、登录、改密码、个人资料 |
| 分类 | 收支分类的增删改查（餐饮 / 交通 / 学习…） |
| 记账 | 流水的增删改查，按日期 / 分类 / 金额筛选，分页 |
| 预算管控 | 月度预算设置、超支提醒（超 80% / 100% 返回预警字段） |
| 报表 | 月度汇总、分类占比、趋势对比（`GROUP BY` 练习场） |

### 核心表初步设计

```
users        (id, username, password_hash, role, created_at)
categories   (id, user_id, name, type[income/expense], icon)
transactions (id, user_id, category_id, amount, type, occurred_at, note)
budgets      (id, user_id, month, amount, category_id?)
```

### 建议实施顺序

1. **用户 + 记账 CRUD**（先把主链路打通）
2. **预算 + 报表**（练聚合查询与业务规则）
3. **权限 + 部署**（收尾，形成可演示系统）

> 提示：表设计先画 ER 图再写代码，能省掉一半返工。

## 三个最常见的坑

1. **在 `async def` 里写同步阻塞代码**
   同步 DB 驱动、`requests`、`time.sleep` 都会卡住事件循环。要么全同步用 `def`，要么全异步用异步驱动，别混用。

2. **教程版本过期**
   Pydantic v1 与 v2 语法不同（`orm_mode` → `from_attributes`）；SQLAlchemy 1.4 与 2.0 写法不同。看到旧代码先确认版本。

3. **只看不写**
   FastAPI 语法很浅，难点在数据库设计、鉴权、工程结构。每阶段必须留下一个能跑的仓库。
